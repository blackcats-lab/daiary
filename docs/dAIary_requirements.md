## 1. プロジェクト概要

### 1.1 プロダクトビジョン

dAIary（ダイアリー）は、写真で日々を記録し、AIが言葉を添えるフォトダイアリーアプリケーションである。スマートフォンで撮影した画像を生成AIに読み取らせ、おしゃれなハッシュタグや投稿文を自動生成する。生成されたテキストはクリップボードコピーやOS標準の共有機能を通じて任意のアプリへ連携可能。サブスクリプション課金（月額480円）による収益化を行う。

### 1.2 ターゲットユーザー

| ユーザー層 | 特徴 | 主な利用シーン |
|---|---|---|
| SNS発信者 | 投稿用テキストを効率的に作りたい | 日常的なSNS投稿文の作成補助 |
| 個人ユーザー | 写真を気軽に管理・共有したい | 旅行・イベントの写真整理 |
| 中小企業・店舗 | 商品やサービスのプロモーション素材を作りたい | 販促用キャプション・ハッシュタグの作成 |
| カメラ愛好家 | 撮影した写真を整理・管理したい | 作品のアルバム管理 |

### 1.3 対応プラットフォーム

- iOS 15.0以上
- Android 10（API Level 29）以上

## 2. 機能要件

### 2.1 カメラ撮影機能

#### F-CAM-001: カメラ撮影

- アプリ内からカメラを起動し写真を撮影できる
- フロントカメラ / リアカメラの切替に対応
- フラッシュのON / OFF / 自動の切替に対応
- グリッドライン（三分割構図ガイド）の表示切替が可能
- 撮影した写真はアプリ内ストレージおよび端末のフォトライブラリに保存

#### F-CAM-002: フォトライブラリからの取り込み

- 端末のフォトライブラリから既存の写真を選択・取り込みできる
- 複数枚同時選択に対応（最大10枚）

#### F-CAM-003: 画像前処理（必須）

- 撮影・取り込み後に自動で以下の前処理を実行:
  - 長辺1024pxへのリサイズ
  - JPEG品質80%への圧縮
  - HEIC形式の自動JPEG変換
- flutter_image_compressパッケージを使用
- 前処理により画像トークンを約3〜5倍削減、アップロード時間も短縮
- デバッグ用にリサイズ後画像のプレビュー機能を実装

#### F-CAM-004: 基本的な写真編集

- トリミング（自由比率・1:1・4:3・16:9）
- 回転（90度単位）
- 明るさ・コントラスト・彩度の調整
- フィルタ適用（プリセット10種類以上）

### 2.2 生成AI機能

#### F-AI-001: ハッシュタグ自動生成

- 写真の内容をAIが解析し、関連するハッシュタグを自動生成する
- 用途に応じた最適なハッシュタグ数を提案
  - 少なめ（3〜5個）: X・Facebook向け
  - 多め（10〜30個）: Instagram向け
- 日本語 / 英語のハッシュタグに対応
- ユーザーが生成結果を編集・追加・削除できる
- 生成結果のクリップボードコピー機能

#### F-AI-002: 投稿文自動生成

- 写真の内容と指定された雰囲気に基づいて投稿文を自動生成する
- 選択可能な文章スタイル:
  - **ポエム風:** 感性豊かな表現、比喩を多用
  - **ビジネス風:** フォーマルで簡潔、プロフェッショナルな印象
  - **カジュアル風:** 親しみやすい口語体、絵文字を適度に使用
  - **ニュース風:** 事実ベースの客観的な文章
  - **ユーモア風:** ウィットに富んだ面白い表現
  - **カスタム:** ユーザーが自由にプロンプトで指示
- 文章長の指定（短文・中文・長文）
- 日本語 / 英語での生成に対応
- 生成結果の再生成（リトライ）機能
- ユーザーによる生成結果の手動編集
- 生成結果のクリップボードコピー機能

#### F-AI-003: 構造化出力

- Gemini APIのresponse_schemaパラメータでJSON Schema指定
- 不要な前置き文を排除し、出力トークンを最小化
- レスポンスは構造化JSON形式で返却

#### F-AI-004: 共有機能

- 生成したハッシュタグ・投稿文をOS標準の共有シートで外部アプリに連携
- 写真 + 生成テキストをまとめて共有可能
- クリップボードへの一括コピー（ハッシュタグ + 投稿文）

#### F-AI-005: AIモデル構成

- 初期モデル: Gemini 2.5 Flash-Lite
  - 最安・マルチモーダル・構造化出力対応
  - 料金: $0.10/1M入力トークン、$0.40/1M出力トークン
  - 1Mトークンのコンテキストウィンドウ
- モデル切替を柔軟に行えるアーキテクチャ
  - AIモデル呼び出しをサービス層で抽象化し、モデル名・エンドポイント・パラメータを設定値として外出し
  - 将来的なモデルカスケード: 通常はFlash-Lite、複雑な画像のみFlashやProに自動エスカレーション
  - Gemini以外のモデル（Claude, GPT等）への切替も設定変更のみで対応可能な設計

### 2.3 アルバム機能

#### F-ALB-001: アルバム管理

- ユーザーが自由にアルバムを作成・編集・削除できる
- アルバム名・カバー写真の設定
- 写真のアルバムへの追加・移動・複製
- アルバム内写真の並べ替え（日付順・手動）
- アルバムの共有リンク生成（公開 / 非公開設定）

#### F-ALB-002: 写真管理

- 写真一覧表示（グリッドビュー / リストビュー）
- 写真の詳細表示（EXIF情報・撮影日時・位置情報）
- お気に入りマーク
- 写真の削除（ゴミ箱機能・30日後自動削除）
- 写真の検索（AI解析によるタグベース検索）

#### F-ALB-003: クラウド同期

- Supabase Storageを利用した写真のクラウドバックアップ
- デバイス間の同期（同一アカウントでの利用）
- ストレージ容量管理（無料プラン: 1GB / サブスクリプション: 50GB）

### 2.4 課金・サブスクリプション

#### F-PAY-001: 無料プラン（Free）

- カメラ撮影・写真取り込み: 無制限
- AI生成回数: 1日10回まで
- クラウドストレージ: 1GB
- 広告表示あり

#### F-PAY-002: プレミアムプラン（Premium）

- 月額: 480円（税込）
- 年額: 4,800円（税込）※v1.1以降で追加予定
- AI生成回数: 制限緩和（1日100回まで）
- クラウドストレージ: 50GB
- 広告非表示
- 優先サポート

#### F-PAY-003: 課金基盤（RevenueCat）

- RevenueCatによるiOS/Android横断のサブスクリプション管理
- Apple/Googleのレシート検証をRevenueCatが代行
- サブスク状態の変更をWebhookでSupabase Edge Functionに通知
- Edge Functionがsubscriptionsテーブルを更新
- 月収$2,500まで無料
- 無料トライアル期間: 7日間

#### F-PAY-004: 広告掲載

- 広告プラットフォーム: Google AdMob
- 広告形式:
  - バナー広告: 画面下部に常時表示
  - インタースティシャル広告: AI生成完了後に表示（5回に1回）
  - リワード広告: AI生成回数の追加獲得（1回視聴で+3回）
- プレミアムユーザーは全広告非表示

### 2.5 ユーザー管理

#### F-USR-001: 認証

- Supabase Authを利用
- メールアドレス + パスワードによるサインアップ / ログイン
- Googleアカウントでのソーシャルログイン
- Apple IDでのサインイン（iOS必須）
- パスワードリセット（メール認証）
- JWTはSupabase Edge Functions呼び出し時に自動付与
- JWTの期限・更新フローの実装

#### F-USR-002: プロフィール

- ユーザー名・アバター画像の設定
- 利用統計（AI生成回数・ストレージ使用量）の表示
- アカウント削除機能

#### F-USR-003: 設定

- 通知設定（プッシュ通知の ON / OFF）
- デフォルト生成スタイルの設定
- デフォルト生成言語の設定
- テーマ設定（ライト / ダーク / システム連動）
- プライバシーポリシー・利用規約の表示

## 3. 非機能要件

### 3.1 パフォーマンス

- アプリ起動時間: 3秒以内（コールドスタート）
- カメラ起動時間: 1秒以内
- AI生成レスポンス時間: 5秒以内（ハッシュタグ）/ 8秒以内（投稿文）
- 画像アップロード: 前処理後の画像（≤2MB）を5秒以内に完了（4G回線）
- オフライン時の基本操作（撮影・アルバム閲覧）に対応

### 3.2 セキュリティ

| 対策項目 | 実装内容 |
|---|---|
| APIキー保護 | Supabase Secretsに保管。Flutterには絶対に含めない |
| 認証 | Supabase AuthによるJWT認証 |
| アクセス制御 | RLS（Row Level Security）を全テーブルで有効化 |
| 濫用防止 | Edge Functionで利用回数制限・リクエストサイズ制限（≤2MB） |
| レシート検証 | RevenueCat経由でサーバー側検証（クライアント検証は使わない） |
| コスト上限 | 1ユーザーあたりの月次上限（例: 1万回）を設定 |

### 3.3 信頼性・可用性

- サーバーサイド可用性: 99.5%以上（月間）
- データバックアップ: 日次自動バックアップ
- 障害時のグレースフルデグラデーション（AI機能停止時も撮影・アルバム機能は利用可能）
- エラー時の利用回数返却（成功時のみカウント）

### 3.4 拡張性

- ユーザー数10万人規模までのスケーラビリティを初期設計で考慮
- 将来的な機能追加（動画対応・AI画像加工・SNS直接連携等）を見据えたアーキテクチャ
- AIモデルの切替を設定変更のみで対応可能なサービス層設計
- モデルカスケード: 必要に応じてFlash-Lite → Flash → Proへの自動エスカレーション

## 4. システムアーキテクチャ概要

### 4.1 リポジトリ構成

モノレポ構成を採用し、モバイル・Supabase設定・ドキュメントを単一リポジトリで管理する。

```
daiary/                    # モノレポルート
├── mobile/               # Flutter アプリ
├── supabase/             # Edge Functions・マイグレーション・RLSポリシー
├── docs/                 # 共有ドキュメント
└── docker-compose.yml    # ローカル開発環境
```

## 5. データモデル（主要エンティティ）

### 5.1 課金・利用管理テーブル

#### subscriptions（サブスク状態）
| カラム | 型 | 説明 |
|---|---|---|
| user_id | UUID | PK, FK → auth.users(id) |
| plan | TEXT | 'free' or 'premium' |
| expires_at | TIMESTAMPTZ | プラン有効期限 |
| revenuecat_id | TEXT | RevenueCat ID |
| updated_at | TIMESTAMPTZ | 更新日時 |

#### daily_usage（日次利用カウンタ）
| カラム | 型 | 説明 |
|---|---|---|
| user_id | UUID | FK → auth.users(id) |
| usage_date | DATE | 利用日 |
| count | INT | 利用回数（PK: user_id + usage_date） |

#### usage_logs（利用ログ）
| カラム | 型 | 説明 |
|---|---|---|
| id | UUID | PK |
| user_id | UUID | FK → auth.users(id) |
| created_at | TIMESTAMPTZ | 作成日時 |
| model | TEXT | 使用モデル名 |
| input_tokens | INT | 入力トークン数 |
| output_tokens | INT | 出力トークン数 |
| cost_usd | NUMERIC(10,6) | コスト（USD） |

カウンタ更新は競合を避けるためPostgres関数（RPC）でアトミックに実行。書き込みはEdge Functionのservice_roleからのみ許可。

### 5.2 写真・アルバム管理テーブル

#### photos（写真）
| カラム | 型 | 説明 |
|---|---|---|
| id | UUID | PK |
| user_id | UUID | FK → auth.users(id) |
| storage_path | TEXT | Supabase Storage パス |
| thumbnail_path | TEXT | サムネイルパス |
| original_filename | VARCHAR | 元ファイル名 |
| file_size | BIGINT | ファイルサイズ(bytes) |
| width | INT | 画像幅 |
| height | INT | 画像高 |
| exif_data | JSONB | EXIF情報 |
| ai_tags | JSONB | AI解析タグ |
| is_favorite | BOOLEAN | お気に入りフラグ |
| deleted_at | TIMESTAMPTZ | 論理削除日時 |
| created_at | TIMESTAMPTZ | 作成日時 |

#### albums（アルバム）
| カラム | 型 | 説明 |
|---|---|---|
| id | UUID | PK |
| user_id | UUID | FK → auth.users(id) |
| name | VARCHAR | アルバム名 |
| cover_photo_id | UUID | FK → photos |
| is_public | BOOLEAN | 公開フラグ |
| share_token | VARCHAR | 共有用トークン |
| created_at | TIMESTAMPTZ | 作成日時 |
| updated_at | TIMESTAMPTZ | 更新日時 |

#### album_photos（アルバム-写真中間テーブル）
| カラム | 型 | 説明 |
|---|---|---|
| album_id | UUID | FK → albums |
| photo_id | UUID | FK → photos |
| sort_order | INT | 並び順 |
| added_at | TIMESTAMPTZ | 追加日時 |

全テーブルでRLSを有効化必須。

## 7. 制約事項・リスク

### 7.1 技術的制約

- Supabase Edge Functionsの実行時間制限（最大150秒）に注意
- Gemini APIの利用料金がユーザー数増加に伴いスケールするため、コスト管理が重要
- 写真のクラウドストレージ容量がユーザー数に比例して増加するため、ストレージコストの監視が必要
- リクエストサイズ上限2MBにより、高解像度画像は前処理必須

### 7.2 ビジネスリスク

- App Store / Google Playの審査ポリシー（特に広告に関するガイドライン）への準拠
- 生成AIによる不適切コンテンツ生成のリスク（コンテンツフィルタリングの実装が必要）
- Gemini APIの仕様変更・料金改定への対応（モデル切替可能な設計で軽減）
- RevenueCatの料金体系変更リスク（月収$2,500超で有料化）

## 8. 用語定義

| 用語 | 定義 |
|---|---|
| AI生成回数 | ハッシュタグ生成または投稿文生成を1回実行することを1回とカウント |
| 投稿文スタイル | AI生成時に指定する文章の雰囲気・トーンの種類 |
| RLS | Row Level Security。Supabaseのデータベースレベルでのアクセス制御 |
| Edge Function | Supabase上で実行されるDeno/TypeScriptベースのサーバーレス関数 |
| 構造化出力 | Gemini APIのresponse_schemaでJSON形式を指定する出力方式 |
| モデルカスケード | リクエスト内容に応じて異なるAIモデルに振り分ける仕組み |
